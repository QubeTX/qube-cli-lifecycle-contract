# Conformance fixtures

Fixtures describe abstract starting state, operation, injected fault, and required observation.
Products implement equivalent local fixtures using their own paths, registries, receipts, package
tools, process controls, and data roots. Fixture IDs and covered obligation IDs remain stable.

A fixture pass proves only the modeled behavior. Cases whose postconditions mention a real package,
fresh terminal, elevation, signature, GUI, restart, or public asset also require target-installed
evidence in the adopter completion receipt.
